# خادم API — نظام مديرية أوقاف السويداء

## تنبيه صادق قبل كل شيء

لا يوجد نظام "غير قابل للاختراق نهائياً" بشكل مطلق — أي شخص يعدك بذلك إما لا يفهم الأمان
أو غير صادق معك. ما بُني هنا يطبّق مجموعة قوية ومعروفة من ممارسات الأمان الصناعية لتقليل
المخاطر إلى أدنى حد ممكن واقعياً. الأمان عملية مستمرة، وليس ميزة تُفعَّل مرة واحدة.

## ما الذي يوفره هذا الخادم فعلياً

- **كلمات سر مشفّرة بالكامل** بخوارزمية bcrypt (12 جولة تشفير) — لا يمكن لأحد قراءتها
  حتى لو وصل مباشرة إلى قاعدة البيانات.
- **تسجيل دخول حقيقي** عبر JWT قصير العمر (15 دقيقة) محفوظ في كوكي `httpOnly` (لا تقدر
  JavaScript بالمتصفح قراءته، وبالتالي محمي من هجمات XSS)، مع توكن تحديث (refresh) طويل
  العمر يُخزَّن مُشفَّراً (hash) في قاعدة البيانات ويُدوَّر (rotated) بكل استخدام.
- **قفل تلقائي للحساب** بعد عدد محاولات دخول فاشلة محدد في `.env`.
- **صلاحيات مفروضة فعلياً على الخادم** (RBAC) — كل مسار API يتحقق من صلاحية المستخدم
  قبل تنفيذ أي شيء، وليس فقط إخفاء زر في الواجهة.
- **حماية CSRF** بنمط التقديم المزدوج (double-submit cookie).
- **حماية من حقن SQL** — كل استعلام معامل (parameterized) عبر مكتبة `pg`، لا يوجد أي
  دمج نصي مباشر لمدخلات المستخدم داخل جملة SQL في أي مكان بالكود.
- **تحقق صارم من كل مدخل** عبر مكتبة `zod` قبل لمس قاعدة البيانات.
- **تحديد معدل الطلبات (rate limiting)** على تسجيل الدخول وعلى كامل الـ API.
- **ترويسات أمان HTTP** عبر `helmet` (منع Clickjacking، تعطيل تخمين نوع المحتوى، إلخ).
- **سجل تدقيق تلقائي كامل** في قاعدة البيانات (من `schema.sql`) يسجّل من فعل ماذا ومتى،
  مربوط بهوية المستخدم الحقيقي عبر كل طلب.
- **رسائل خطأ عامة** لا تكشف تفاصيل داخلية (لا Stack Trace يصل للمستخدم في بيئة الإنتاج).

## ما هو مسؤوليتك أنت (خارج نطاق الكود)

هذا الكود وحده لا يكفي لنظام آمن — الأمان طبقات:

1. **HTTPS إلزامي** — شغّل هذا الخادم خلف وسيط عكسي (nginx أو Caddy) مع شهادة TLS حقيقية
   (Let's Encrypt مجاني). لا تعرّض المنفذ 4000 مباشرة على الإنترنت أبداً.
2. **جدار حماية (Firewall)** — افتح فقط المنافذ 80/443 للعامة، وأغلق كل شيء آخر (خصوصاً
   منفذ PostgreSQL 5432 — يجب ألا يكون متاحاً من الإنترنت العام إطلاقاً).
3. **أسرار حقيقية** — ولّد `JWT_ACCESS_SECRET` و`JWT_REFRESH_SECRET` وكلمة سر
   `awqaf_app` بأمر مثل:
   ```
   node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
   ```
   ولا تضعها أبداً في Git. استخدم ملف `.env` محلياً، أو خدمة أسرار حقيقية على الخادم.
4. **نسخ احتياطي دوري لقاعدة البيانات** ومُختبر الاستعادة فعلياً.
5. **تحديثات دورية** — شغّل `npm audit` بشكل منتظم وحدّث الحزم، خصوصاً عند ظهور ثغرات معروفة.
6. **مراجعة أمنية مستقلة (Penetration Test)** قبل أي إطلاق رسمي فعلي، خصوصاً إذا كان
   النظام سيحتوي بيانات مالية أو شخصية حساسة ويُنشر على الإنترنت العام.
7. **لا تُشغّل هذا الخادم بحساب قاعدة بيانات "superuser"** — استخدم حساب `awqaf_app`
   المحدود الصلاحيات المُعرَّف في `schema.sql` فقط.

## التشغيل المحلي (للتجربة)

```bash
# 1) ثبّت الحزم
cd backend
npm install

# 2) جهّز قاعدة البيانات (مرة واحدة)
psql "postgresql://USER:PASS@localhost:5432/postgres" -c "CREATE DATABASE awqaf_sweida;"
psql "postgresql://USER:PASS@localhost:5432/awqaf_sweida" -f ../database-schema.sql

# 3) انسخ ملف البيئة واملأه بقيم حقيقية
cp .env.example .env
# عدّل .env: كلمة سر awqaf_app، أسرار JWT، CORS_ORIGIN...

# 4) أنشئ أول حساب مدير نظام
node scripts/create-admin.js admin "مدير النظام" "كلمة-سر-قوية-جداً-2026!"

# 5) شغّل الخادم
npm start
```

الخادم يستمع افتراضياً على `http://localhost:4000`. جميع المسارات تحت `/api/...`.

## نقاط النهاية (Endpoints) الكاملة

كل الوحدات مبنية الآن بنفس مستوى الحماية (صلاحيات + تحقق + معاملات آمنة):

| المسار | الطريقة | الوصف | يتطلب صلاحية |
|---|---|---|---|
| `/api/auth/login` | POST | تسجيل الدخول | — |
| `/api/auth/refresh` | POST | تجديد الجلسة | كوكي refresh صالح |
| `/api/auth/logout` | POST | تسجيل الخروج | مسجّل دخول |
| `/api/auth/me` | GET | بيانات المستخدم الحالي | مسجّل دخول |
| `/api/auth/change-password` | POST | تغيير كلمة السر الخاصة | مسجّل دخول |
| `/api/users` | GET/POST | عرض/إضافة مستخدمين | `users.manage` |
| `/api/users/:id` | PATCH | تعديل دور/تفعيل مستخدم | `users.manage` |
| `/api/users/:id/reset-password` | POST | إعادة تعيين كلمة سر مستخدم | `users.manage` |
| `/api/users/roles` | GET | قائمة الأدوار المتاحة | `users.manage` |
| `/api/mosques` | GET/POST/PUT/DELETE | المساجد (كل الحقول) | `mosques.read` / `mosques.write` |
| `/api/projects` | GET/POST/PUT/DELETE | المشاريع | `projects.read` / `projects.write` |
| `/api/price-quotes` | GET/POST/PUT/DELETE | عروض الأسعار | `projects.read` / `projects.write` |
| `/api/contracts` | GET/POST/PUT | العقود (لا حذف نهائي) | `projects.read` / `projects.write` |
| `/api/engineer-statements` | GET/POST/PUT/DELETE | كشوف المهندسين | `projects.read` / `projects.write` |
| `/api/disbursements` | GET/POST/PUT | أوامر الصرف (لا حذف نهائي، والمبلغ يُتحقق تلقائياً ضد قيمة المشروع) | `projects.read` / `projects.write` |
| `/api/circles` | GET/POST/PUT/DELETE | الحلقات القرآنية | `education.read` / `education.write` |
| `/api/schools` | GET/POST/PUT/DELETE | المدارس الشرعية | `education.read` / `education.write` |
| `/api/archive` | GET/POST/PUT/DELETE | الأرشيف | `archive.read` / `archive.write` |
| `/api/budgets` | GET/POST/PUT | الميزانية (لا حذف نهائي) | `finance.read` / `budgets.write` |
| `/api/transactions` | GET/POST/PUT | المعاملات المالية (لا حذف — انظر أدناه) | `finance.read` / `finance.write` |
| `/api/transactions/:id/void` | POST | إلغاء معاملة مالية (بدل الحذف) مع سبب إلزامي | `finance.void` |
| `/api/transactions/categories` | GET | قائمة بنود التصنيف المالي | `finance.read` |
| `/api/employees` | GET/POST/PUT | التنمية الإدارية — بيانات حساسة، لا حذف نهائي | `employees.read` / `employees.write` |
| `/api/settings` | GET/PUT | إعدادات المديرية | `settings.manage` |
| `/api/audit-log` | GET | سجل التدقيق الكامل (قراءة فقط) | `audit.read` |

ملاحظات مهمة:
- **لا يوجد حذف نهائي إطلاقاً** للمعاملات المالية، الميزانية، العقود، أوامر الصرف،
  أو سجلات الموظفين — هذا مفروض على مستوى قاعدة البيانات نفسها (`REVOKE DELETE`
  أو RLS بدون سياسة حذف)، وليس فقط باتفاقية بالكود. حتى لو أخطأ المبرمج لاحقاً
  ومنح صلاحية حذف بالخطأ من الواجهة، قاعدة البيانات ترفض العملية فعلياً.
- **بيانات الموظفين (`/api/employees`) حساسة بشكل خاص** (رقم وطني، رواتب) —
  محمية بطبقتين مستقلتين: صلاحية `employees.read/write` على الخادم، وسياسة
  Row-Level Security على قاعدة البيانات تقصر القراءة على مدير النظام والمدير
  المسؤول وموظف إدخال البيانات فقط.
- جدول التحقق الكامل بين كل مسار وحقوله وأعمدة قاعدة البيانات المطابقة له
  تم فحصه آلياً (كل مفتاح بمخطط zod له عمود مطابق بقاعدة البيانات والعكس)
  قبل تسليم هذا الكود — راجع `src/utils/crudFactory.js` لفهم النمط المشترك.

بقية الوحدات (المشاريع، العقود، إلخ) تُبنى بنفس نمط
`src/routes/mosques.routes.js` أو عبر `makeCrudRouter` في `src/utils/crudFactory.js`
للوحدات الأبسط — راجع أي ملف `*.routes.js` كمرجع لإضافة وحدات مستقبلية.

## طريقة الاتصال من الواجهة الأمامية

- كل الطلبات يجب أن ترسل `credentials: 'include'` (fetch) حتى تُرسَل الكوكيز.
- بعد تسجيل الدخول، اقرأ كوكي `csrf_token` (غير httpOnly) وأرسل قيمته في ترويسة
  `X-CSRF-Token` مع أي طلب POST/PUT/PATCH/DELETE.
- التوكن الأساسي يتجدد تلقائياً — إذا رجع الخادم 401، نادِ `/api/auth/refresh` ثم
  أعد المحاولة؛ إذا فشل التجديد أيضاً، أعد المستخدم لصفحة تسجيل الدخول.
